# Tenant Role Catalogue

## Purpose

The **Tenant Role Catalogue** HTML web resource helps administrators review Dataverse security roles across environments by combining same-environment Dataverse reads with imported Power Automate admin collector output.

It is designed for scenarios like:

- Loading roles from the current Dataverse environment
- Importing tenant-wide role inventory generated by a Power Automate cloud flow
- Comparing roles by environment, business unit, managed state, and source
- Exporting normalized role inventory to JSON or CSV
- Generating explicit multi-environment role-create request JSON for a reviewed automation flow
- Handling missing or unavailable **Power Platform for Admins V2** actions through legacy connector or manual environment-list fallbacks

## Where to use it

Install the Dataverse HTML Tools Suite to get Tenant Role Catalogue as a bundled standalone page in the `Admin Tools` model-driven app. For partial or source-only deployments, you can still add `src\TenantRoleCatalogue.html` as a Dataverse **Webpage (HTML) web resource**, then add it to an admin model-driven app as a standalone page/navigation item.

The browser page runs in the signed-in user's Dataverse context. Tenant-wide discovery and cross-environment role reads must come from an imported Power Automate collector JSON file or another approved backend export. The Suite bundles this HTML UI; it does not install the collector or role-create cloud flows.

## Main workflow

1. Open **Tenant Role Catalogue** from the Suite `Admin Tools` app, or from another admin model-driven app where the standalone HTML web resource is deployed.
2. Use **Load current environment roles** to catalogue roles visible in the hosting environment.
3. Run the separately configured Power Automate collector flow for tenant-wide role inventory.
4. Import the generated JSON with **Power Automate collector JSON**.
5. Filter by environment, role name, business unit, managed state, or source.
6. Export the normalized catalogue to JSON or CSV.
7. When creating roles across environments, generate a role-create request JSON file and run it through a reviewed Power Automate flow.

## Power Automate integration

The preferred tenant inventory path is a manually triggered cloud flow that:

1. Discovers environments with **Power Platform for Admins V2**.
2. Falls back to legacy admin connector output or a manually supplied environment array when V2 actions are unavailable.
3. Reads Dataverse security roles in each target environment through an approved Dataverse connection or HTTP action.
4. Writes a JSON export containing `environments[].roles[]` and `failures[]`.

The HTML page accepts multiple collector shapes so the flow can degrade gracefully as connector availability changes:

- `{ "environments": [{ "environmentName": "...", "roles": [] }] }`
- `{ "roles": [] }`
- A flat array of role rows
- Optional `failures`, `errors`, `SkippedEnvironments`, or `EnvironmentFallbacks` arrays

## Role creation

The page does not silently create roles across tenant environments. It generates request JSON with:

- Requested role name
- Optional source role name to clone
- Explicit target environments
- Requested timestamp
- Copy/fallback options

A separate reviewed Power Automate flow should consume that request, resolve the source role and business unit per environment, create the role, copy privileges when requested, and return per-environment results. Importing the Suite does not create or enable this automation.

## Required privileges

The signed-in user needs Dataverse role read access in the current environment.

The Power Automate collector connection needs enough Power Platform and Dataverse admin privileges to:

- List accessible environments
- Read Dataverse roles in each target environment
- Create roles and copy privileges when processing create requests

This tool does not bypass Dataverse, Power Platform, DLP, connector, or tenant security controls.

## Limitations

- Same-environment loading uses only the current Dataverse organization.
- Tenant-wide inventory depends on the imported collector file.
- Role IDs, business units, and privilege records are environment-specific.
- Role names are not unique across business units.
- Partial failure is expected when an admin connection cannot access an environment.

## Troubleshooting

| Symptom | Likely cause |
|---|---|
| Current environment button is disabled | The page is not running inside a Dataverse model-driven app with `Xrm.WebApi` |
| Imported JSON has no roles | Export roles as `environments[].roles[]`, `roles[]`, or a flat array |
| Some environments show failures | The collector lacked access, the environment had no Dataverse URL, or connector actions were unavailable |
| Power Platform for Admins V2 is unavailable | Use the legacy connector action fallback or provide the manual environment array described in the collector guide |
| Generated role-create request is empty | Load or import environments before generating the request |
